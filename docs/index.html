01Save the money

Most medallion ETL is small, frequent batches — clean, filter, join, roll up. A distributed engine is overkill for that. On the identical result (byte-for-byte, parity-checked), leat used ~4.6–9.4× fewer CPU-seconds than Spark. CPU-seconds are what your cloud bill is made of.

A pipeline that runs every few minutes is a cluster rented 24/7 (or a 3-second JVM cold start every trigger) vs. a task that runs ~0.4 s and exits. That gap is structural — roughly 15–100× cheaper.

03Scale like a stateless service

A Spark streaming job is a stateful monolith: scaling means resizing the cluster and restarting the job. leat keeps its offset in the sink's own commit, so a worker holds no durable state.

Scale = replica count

Scaling out is deploying another instance; scaling in is removing one. No cluster resize, no restart, no state to migrate — that's the entire operation. kubectl scale --replicas=8, and anonymous workers self-distribute the partitions.

Failover & blue-green, free

A dead worker's lease expires and a survivor reclaims its partition from the sink offset — exactly-once, no rebalance event. Deploy a green version to a new sink, parity-check, and swap. No stop-the-world upgrades.

04How to use it

If you know Polars, you know leat. Write a DataFrame; offsets are managed for you.

# pip install "git+https://github.com/samtheprogrammer/leat.git"
import leat, polars as pl

lt = leat.connect("/data/leat")
lt.table("db.events").write(pl.DataFrame({"user_id":[1,2,3], "value":[50,150,250]}))

@lt.model(source="db.events", sink="db.silver", start="earliest")
def silver(df):                      # df is just your columns — no _offset
    return df.filter(pl.col("value") > 100)

silver.run(once=True)                # incremental, exactly-once, done
print(lt.table("db.silver").read())  # Polars out
